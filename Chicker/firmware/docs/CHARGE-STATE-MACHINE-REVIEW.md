Source chart: `flowcharts/chicker-charge-state-machine.drawio`. Column 1 is always the chart as drawn; the change
(if any) goes in "Agreed behaviour". Code is only written from this list. Anything in the code that is not on the
chart is listed under "Not on the chart" and needs Henry's OK.

## Charge state machine

| # | Chart element | Agreed behaviour | Notes |
|---|---|---|---|
| 1 | ANY STATE — `chg_ok == 0` → Wait for Bat | As drawn. From every state **except Disabled** (Disabled goes nowhere). CHARGE low when leaving. `chg_ok` = "a battery is present" for the firmware: turns on above 14.7 V, stays on down to 14.3 V (hysteresis, kept from before the review), off above 17.0 V; read every 500 ms, 3-sample debounce. The same window is used everywhere (config `BATT_ON_MIN_V` / `BATT_OFF_MIN_V` / `BATT_MAX_V`). | The autodischarge handles a battery dropping out; better battery detection lives elsewhere. |
| 2 | Wait for Bat — `chg_ok == 1 && chg_stop_mode_ctrl == 0 && chg_disable_chip_level == 0` → Startup (reset vars) | **Changed:** the `chg_disable_chip_level == 0` check is dropped (see the `chg_disable_chip_level` row). With a battery present but `chg_stop_mode_ctrl == 1`, the board stays in Wait for Bat. | The `chg_stop_mode_ctrl` check overlaps with the ANY STATE → Inhibited rule, but is kept. Side effect: at power-up the 2 s battery wait runs after the robot's first CHARGE command, not before. |
| 3 | Startup (reset vars) → New Charge from Bat → Wait for 2s → Charge Toggle Reset from Bat | **As drawn, no change.** Three separate states; "Charge Toggle Reset from Bat" stays separate from "Charge Toggle Reset" so the log shows whether a cycle started from a battery event or a mode event. | 4 | ANY STATE — `chg_stop_mode_ctrl == 1` → Inhibited | **As drawn.** **Inhibited = stop charging and dump the caps.** CHARGE low immediately, mid-cycle included, then the dump. Applies from every state including Startup / New Charge from Bat. | See "ANY STATE rules" below and note N-4. |
| 5 | Inhibited — `chg_ok == 1 && chg_stop_mode_ctrl == 0 && chg_disable_chip_level == 0` → New Charge | **Changed (Henry's updated chart):** `chg_ok == 1 && chg_stop_mode_ctrl == 0` → **Not Charging** (element 5a), not straight to New Charge. The `chg_disable_chip_level == 0` check is dropped (Disabled is one-way). | `chg_stop_mode_ctrl` is set **only by the mode machine**: 1 = stop and dump (Idle, heartbeat loss), 0 in its "Enable Charging" steps. The extra "kicker busy" rule in app.py is removed. If the hold is off, Not Charging passes straight on to New Charge. |
| 5a | **New on Henry's updated chart:** ANY STATE — `chg_ok == 1 && chg_stop_mode_ctrl == 0 && chg_hold_mode_ctrl == 1` → Not Charging; Not Charging — `chg_hold_mode_ctrl == 0` → New Charge | **As drawn (updated chart).** Not Charging = **stop charging, keep the caps charged**: CHARGE low immediately (mid-cycle included), **no dump**. `chg_hold_mode_ctrl` is a veto: it can only stop charging, never start it, and never causes a dump. Not from Disabled or Not Charging itself. | See note N-5. |
| 6 | New Charge — Wait for 50ms → Charge Toggle Reset | **As drawn, no change.** CHARGE low in New Charge; 50 ms timed from entering New Charge. Battery lost → Wait for Bat, stop → Inhibited (ANY STATE rules). | |
| 7 | New Charge / Charge Toggle Reset — GUARD (time since last kick >= 50ms, time since last chg >= 50ms) → Charge Toggle Wait | **Changed:** the GUARD stays here (a condition on the arrow) with **one row only: time since last chg >= 500ms** (time since the last charge cycle started). The two 50 ms rows are dropped. Passing the GUARD raises CHARGE and enters Charge Toggle Wait. | The top-off path needs nothing new: its 5 s timer already spaces cycles. See note N-1. |
| 8 | Charge Toggle Wait — wait for 10ms → `done == 1` → Charge Started / `done == 0` → Charging Disabled | **Changed: the DONE rising edge is latched instead of sampled. No HV check here.** On entering Charge Toggle Wait: clear the DONE edge latch, raise CHARGE. At **50 ms**: <br>• DONE rose since CHARGE went high (latched) → Charge Started (even if `done` is already back to 0) <br>• DONE never rose → **Charging Disabled. UVLO / thermal shutdown** → Disabled (the charger didn't start; also catches a DONE line stuck high or an unpowered LT3750, which give no rising edge either) | **Why the check exists:** it answers "did the charger start?". Without it a dead LT3750 (UVLO, thermal, no power, broken CHARGE / DONE line) keeps `done == 0`, and the 4500 ms check would read that as "finished". **Why latched:** a single sample (10 ms, or 50 ms after Akhil's RoboCup change `3ee2a3c`) can miss a short top-off pulse. That was the bug `CHARGE_ALREADY_FULL_HV` patched. The RP2040 latches GPIO edges in hardware (Pin IRQ on DONE, `IRQ_RISING`, sets a flag), so pulse length and check time no longer matter. A short top-off that already finished just carries on to the 4500 ms check (element 9). Open point: see N-2. |
| 9 | Charge Started — `safe_chg == 1` → GUARD (time since last chg >= 236ms) → Charged to ~50V → wait 5s → Charging Disabled. Too slow to charge → Disabled | **As drawn, kept as a reminder.** Behind config flag `SAFE_CHARGE = 0` (off by default): when 1, charge for 236 ms (~50 V), CHARGE low, wait 5 s, then Disabled (needs a power cycle). | Not used yet; to be built and tested together with the functional board tests later. |
| 10 | Charge Started — `safe_chg == 0` → GUARD (time since last chg >= 4500ms) → `done == 0` → Assuming Normal Operation / `done == 1` → Charging Disabled. Too slow to charge → Disabled | **As drawn, no change** (timer-based, kept for safety). The board waits in Charge Started until 4500 ms after the toggle, then reads `done` once (a steady level by then, so one read is reliable): 0 → Assuming Normal Operation, 1 → Too slow → Disabled. | Voltage + timer idea for later: see N-3. `safe_chg` is element 9. |
| 11 | Assuming Normal Operation — GUARD (time since last chg >= 5000ms) → Charge Toggle → `done == 0` → Charge Toggle Wait / `done == 1` → Charging Disabled. UVLO/thermal | **Changed: removed the `done == 1` → "Charging Disabled. UVLO/thermal" branch at Charge Toggle.** Everything else as drawn: after 5000 ms, Charge Toggle sets CHARGE low for 50 ms (now its own state), then goes to Charge Toggle Wait. | Per the LT3750 datasheet, UVLO / thermal faults pull DONE **low**, so `done == 1` here could never detect them. UVLO / thermal is detected in element 8 instead ("no edge" after a toggle). The datasheet only needs CHARGE low for 20 µs; 50 ms is kept as margin. |
| 12 | orange diamond — `chg_disable_chip_level == 1` → Disabled | **As drawn.** Every charge fault goes to Disabled (one-way, until reboot). **Disabled = CHARGE low and dump the caps** (done by the charge machine itself; the mode machine's Locked only reports it). **On entering Disabled the charge machine sets its output flag `chg_disable_chip_level = 1`** (never cleared). The flag (a) tells the mode machine to stop (→ Locked, mode review) and (b) is sent to the Pi with the fault reason (UVLO / thermal shutdown, Too slow to charge). | See the `chg_disable_chip_level` row and the coupled review. |

| — | ANY STATE rules (both boxes) | An ANY STATE arrow applies from every state **except its own target** and **Disabled** (end state, nothing leaves it). **The battery rule has priority:** with no battery the board goes to and stays in Wait for Bat, also from Inhibited, so the stop rule does not apply in Wait for Bat (otherwise the two rules would bounce the board between Wait for Bat and Inhibited). | |
| — | "Charging Disabled" bubbles (Charging Disabled; Charging Disabled. ## Notes for later

| # | Note |
|---|---|
| N-0 | **Design rule: timing is absolute; a reading carries a risk of being wrong.** The HV sense is expected to work, but as a risk (a failed divider, op-amp or ADC) it could read wrong, while a timer can't. So the decisions the charge cycle depends on (did it start, did it finish, too slow) are made on timers and the DONE pin. HV readings may add protection on top, but don't replace a timer check. |
| N-1 | The timer design answers two different questions. Don't mix them up: <br>**(1) "Are we sure it HAS charged?"** (verification): at 4500 ms after the toggle, `done == 0` → the cycle really finished (Assuming Normal Operation); `done == 1` → too slow → Disabled. <br>**(2) "Has it charged in a while?"** (spacing): the next toggle comes at 5000 ms, i.e. 500 ms after the 4500 ms verification. <br>**If top-off becomes voltage-based** (re-toggle when HV < 200 V instead of at 5 s), both must still be covered: the verification (1) still has to pass before Assuming Normal Operation, and the 5 s spacing (2) goes away, so the top-off path (Charge Toggle → Charge Toggle Wait) would need its own minimum spacing (e.g. >= 500 ms since the last cycle start) so a wrong HV reading can't re-toggle CHARGE rapidly. |
| N-2 | **Bench test needed (element 8):** it isn't confirmed that the LT3750 pulses DONE at all when CHARGE rises on a bank that is *already* at its target. If it doesn't, the latch sees no edge on such a top-off and element 8 would wrongly go to Disabled. Test: with the bank full, toggle CHARGE several times and check the DONE edge latch fires every time. Add this as a step in `bench/bring_up.py`. If it doesn't always fire, revisit element 8 before relying on it. |
| N-3 | **Idea, not adopted yet: voltage AND timer for the top-off / finish checks.** After the initial charge, check HV: below ~190 V → charge again; otherwise wait until 4500 ms as now (which still trips Too slow if it is still charging). Complication: needs a hold-off after the cycle starts, so the low HV *while charging* isn't mistaken for low HV *from discharging*. Kept timer-based for now (element 9) for safety. |
| N-4 | **Inhibited dumps (element 4).** Inhibited = CHARGE low, then the dump (`~DISCHARGE` low), so the charge machine owns the dump. A stop during the 2 s battery wait just goes to Inhibited. The RoboCup code did **not** dump on `chg_stop_mode_ctrl` (only on battery loss / chip disable, see its line 686 comment), so this differs from it. Effect on kicks (Disable Charging before a kick also dumps): coupled review C-1, solved by `chg_hold_mode_ctrl` (element 5a). |
| N-5 | **Not Charging and `chg_hold_mode_ctrl` (element 5a).** <br>• *Why:* the kick and damp paths need "stop charging but keep the energy"; `chg_stop_mode_ctrl = 1` dumps (coupled C-1). <br>• *Why a veto, not a "dump" flag:* independent "stop" and "dump" flags could ask for charging while dumping (the smoking-resistor case). The hold can only stop charging, so no combination can do that (table in the coupled review). <br>• *Order of the ANY STATE rules:* battery (→ Wait for Bat), then `chg_stop_mode_ctrl == 1` (→ Inhibited, dumps), then the hold (→ Not Charging). ANY STATE rules are checked before a state's own arrows. <br>• *Leaving Inhibited:* always via Not Charging, which passes straight on to New Charge if the hold is off. The dump turns off in Not Charging, and New Charge holds CHARGE low 50 ms, so the dump is off before CHARGE rises. <br>• *Hold during the 2 s battery wait:* the hold rule pulls the board out of Startup / New Charge from Bat to Not Charging; when the hold is released it starts with New Charge, so the 2 s battery wait is skipped. It can't happen in practice: the mode machine dumps (`chg_stop_mode_ctrl = 1`) until Idle, and only sets the hold in a kick or damp. |
## TOPIC: what if a reading is stuck (X-1 to X-5, and other HV uses) - DECIDED 2026-10-26

**Decided:** X-1 kept at 220 V (→ Disabled), X-2 / X-3 / X-4 dropped, X-5 kept. Mode HV uses kept as
agreed (stuck low → no kicks / damps: accepted risk). Henry: the HV circuit isn't expected to fail; change things
if it ever causes problems. The analysis below is kept for reference.

Status before deciding: Every option trades goal (1) against goal (2):
**(1)** a working board must never think it's broken and stop kicking in a game;
**(2)** never damage a board (bank caps are rated 250 V; normal full is 206–212 V).
The most likely circuit failure is a reading **stuck at one end**: HV stuck **HIGH ≈ 254 V** (ADC saturated) or
**LOW ≈ 0 V**. Kicks arm only at `HV >= 100V` (mode element 10, accepted risk for stuck LOW, KCK-1); elements 8 and 10 use only timers and
DONE (N-0), so neither stuck case affects them.

| Item | HV stuck HIGH | HV stuck LOW |
|---|---|---|
| **X-1** HV >= 220V → Disabled (**agreed, 220 V**) | Trips → board disabled → no kicks (goal 1 ✗). But a real overvoltage looks the same at first (goal 2). | Never trips → no software overvoltage backstop. The LT3750's own feedback (independent of the MCU's HV sense) still regulates; that is the protection level the RoboCup code had. |
| **X-2** HV >= 220V while charging → Disabled (**dropped**) | Trips like X-1; adds nothing over X-1. | Never trips. |
| **X-3** no HV rise below 150V → Disabled (**dropped**) | No effect. | Every charge "fails" → board disabled → no kicks (goal 1 ✗). Elements 8 / 10 already catch a dead charger. |
| **X-4** fault + battery < 14.3V → Wait for Bat (**dropped**) | Battery ADC, not HV. Worst case one extra retry. | Same. |
| **X-5** power-stage interlock (**agreed: keep**) | Uses no readings. | Uses no readings. |
| Battery reading (element 1 `chg_ok`) | Stuck above 17 V → `chg_ok == 0` → never charges (same as the RoboCup code). | Stuck low → never charges. |
| Mode chart HV uses (kick arm `HV >= 100V` (mode element 10), damp start 180 V, damp duty formula clamp 60 V, kick-ready flag, damp duty) | Kick arms on any bank; damp starts at any real voltage; kick-ready always true. | **Never kicks** (accepted risk, mode KCK-1); damping never runs; kick-ready never true. Settle in the mode review. |

Ideas on the table (none adopted):
- Drop X-2 and X-3.
- "HV sense stuck" detector that **warns the Pi** (HV unknown in STATUS) instead of disabling. Stuck high = at the rail, or not
  falling while dumping. Stuck low = still ≈ 0 V after element 10 verified a full cycle.
- X-1 "dump and verify": on HV >= 225 V stop charging and dump; reading falls → real → Disabled; reading stays pinned →
  sense stuck → warn the Pi and keep charging on timers / DONE (LT3750 regulation only).
- Same warning treatment for a stuck battery reading.
- Use the simulator to try each option against stuck-high / stuck-low faults and a real LT3750 runaway, to see
  what each option costs for goals (1) and (2) before deciding.
## LT3750 facts (datasheet rev A, for reference)

| Fact | Datasheet |
|---|---|
| DONE is the only status output (open collector, needs a pull-up). There is no separate fault pin. | Pin 2 description |
| DONE goes **LOW** (NPN on) when the target voltage is reached, **and also on any fault**: "Any fault conditions such as thermal shutdown or undervoltage lockout will also turn on the NPN." So DONE alone can't tell "finished" from "faulted". | Pin 2 description |
| While charging, the NPN is off, so DONE reads **HIGH** through the pull-up. | Operation, pin 2 |
| A fault resets the master latch ("remain in the set state until the target output voltage is reached or a fault condition resets it"), so charging stops. | Operation, 1. Start-Up |
| UVLO: VCC below 2.8–3 V or VTRANS below 2.5–3 V. Thermal shutdown: die temperature 160 °C. | Electrical characteristics, block diagram |
| CHARGE: a rising edge starts a cycle (start-up ~20 µs); low = shutdown. **Minimum CHARGE low time between cycles: 20 µs.** Needs a ≥ 1 V/µs edge (a GPIO is fine). Enable ≥ 1.1 V, disable ≤ 0.2 V. | Pin 3, electrical characteristics |
